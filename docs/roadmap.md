# Boilerplate 로드맵 (초안)

README의 "아직 없는 것" 목록과 최근 커밋(채팅 → React Compiler → OIDC 로그인) 흐름을 근거로 정리한 제안입니다.
확정된 전제([CLAUDE.md](../CLAUDE.md))는 건드리지 않으며, 우선순위는 사람이 정합니다.

## 현재 위치

- 완료: 검증 파사드, UTC 시간 정책, 페이지네이션 규약, Postgres/in-memory, pub/sub·presence(Redis),
  버전 핸드셰이크, 디자인 시스템, 채팅(실시간·접속자·보존 정책·부하 테스트), React Compiler,
  회원 서버 연동(OIDC) + 회원/게스트 구분.
- 열린 이슈: 없음 (2026-10-15 기준).

## 단계

```
Now ──────────────► Next ──────────────► Later
정합성 마무리        기능 깊이              운영·확장
```

### Now — 방금 들인 것의 빈틈 메우기

| 항목                               | 이유                                    | 비고                                             |
| ---------------------------------- | --------------------------------------- | ------------------------------------------------ |
| todos ↔ 회원 연결(소유자)          | 지금은 회원 모두가 한 목록을 공유       | 마이그레이션 + 업그레이드 가이드 필요            |
| 감사 로그의 행위자                 | 소유자와 같은 변경에서 `caller.id` 기록 | 위와 한 묶음                                     |
| 다른 서비스가 회원 정보를 묻는 API | client credentials 호출 경로 확정       | 회원 서버 쪽과 계약 조율 필요                    |
| 채팅 도배 제한                     | 게스트 무제한 전송이 열려 있음          | 방 정책(`ChatRoomPolicy`)에 넣는 안이 자연스러움 |
| 채팅 지난 채팅 더 불러오기         | 커서(`before`) 방향 추가                | 기존 `after` 커서와 대칭                         |

### Next — 기능 깊이

- 채팅: 입력 중·읽음 표시, 메시지 수정·삭제.
- 채팅: 비공개 방과 운영자 역할 (회원 전제가 필요 → todos 소유자 작업 이후).
- 외부 로그인(구글 등)은 **회원 서버 저장소**의 일. 이 저장소는 OIDC 표준 유지, 변경 없음 예상.
- E2E 스모크 테스트: `testid` 레지스트리가 이미 있어 비용이 낮음.

### Later — 운영·확장

- 관측성: 구조화 로그, 요청 id, 메트릭 (`/health` 위에 얹기).
- 배포 파이프라인 예시 (Docker 이미지 → 롤링 배포, 이미 있는 graceful shutdown·버전 핸드셰이크 활용).
- Redis presence 계약 테스트를 CI 선택 잡으로 상시화.
- `compiler:report`를 CI에서 회귀 감시로 사용.

## 사람에게 확인할 결정

1. todos 소유자 모델: 회원별 목록으로 갈지, 공유 목록 + 작성자 표시로 갈지.
2. 도배 제한 기준: 방 정책별 설정 vs 전역 기본값.
3. 다른 서비스용 회원 조회 API를 이 저장소가 아닌 회원 서버가 제공해야 하는지.

## 규칙

- 다운스트림이 머지만으로 끝나지 않는 변경(마이그레이션 등)은 `docs/upgrade-guides/`에 가이드를 함께 추가.
- 각 항목은 `bun run check` 통과 후 PR 단위로 나눔.
